## Findings that remain open in the reachable code

### P1 — R1: 5m structure reset boundary is still lost

- `StructureResult` has `events`, `pivots`, and `pools`, but no `segment_starts`.
- `detect_structure` segments the input using `_segment(bars, calendar, "5m")`, but only flattens the resulting events into the returned object.
- `ranking.py::structure_score` still infers the active segment with `_segment(window, calendar, "15m")`.

Thus the reachable implementation still cannot see an intraday 5m gap boundary when the corresponding 15m series remains continuous. The pre-gap BOS can still leak into the post-gap Stage 1 structure state. The R1 fix described by Claude is not present in the reachable code.

### P1 — R2: RS still does not verify actual interval duration

`rs_score` checks that stock and Nifty timestamps agree at the same array indices. It still computes 15m/30m/60m intervals by offsets `(1, 2, 4)` and does not verify that the current-to-prior timestamps span exactly 15, 30, and 60 minutes.

If both series omit the same 15m slot, their selected timestamps can match while the supposed 60-minute return spans 75 minutes. The R2 correction described in 041 is not present.

### P2 — R5: missing baseline still changes tie order

The current shortlist key ranks any candidate with a volume ratio ahead of every candidate without one. That means availability itself affects the tie-break, contrary to §4.2's rule that volume plays no role when its baseline is unavailable. The proposed compare-only-when-both-ratios-exist fix is not present.

### P2 — R7: README remains contradictory

The current README's top status claims 90-day SmartAPI coverage for 49/50 constituents plus Nifty, but its "Current state" paragraph still says the historical cash-equity data source is not confirmed as available. The correction described in 041 is not present.
